# ADR-007 공공 API 호출 안정성

- 상태: 승인

## 맥락

실제 호출에서 확인한 공공데이터 게이트웨이의 동작은 다음과 같다.

| 현상 | 확인 방법 |
|---|---|
| Java HttpClient의 기본 HTTP/2 협상 시 응답 없이 멈춤. HTTP/1.1로는 0.1~0.7초 | 같은 요청을 HTTP/1.1과 HTTP/2로 각각 보내 비교 |
| 간헐적으로 504 `SERVICETIMEOUT_ERROR` | 수집·검증 중 여러 차례 발생 |
| 인증키 오류는 403과 사유 코드(30 등)로 응답 | 응답 본문 확인 |
| 포털이 인증키를 Encoding/Decoding 두 형태로 보여 줌. Encoding 키를 그대로 쓰면 이중 인코딩으로 403 | 두 키로 각각 호출 |

## 결정

| 항목 | 결정 |
|---|---|
| 프로토콜 | HTTP/1.1 고정 |
| 타임아웃 | 연결 5초, 응답 전체(본문 포함) 60초. 서울 1페이지(약 8MB)는 평소 1~2초 |
| 재시도 | 네트워크 오류와 5xx만, 2초 간격으로 최대 3회 시도(첫 호출 포함, 재시도 2회). 인증키 오류 등 4xx는 바로 실패 |
| 전체 동기화 실패 | 10분, 20분, 40분… 최대 4시간 간격으로 다시 시도. 재시도해도 나아지지 않는 오류(인증키)는 정기 동기화까지 기다림 |
| 페이지 실패 | 한 페이지가 실패해도 나머지는 반영 (정리는 건너뜀, ADR-002) |
| 인증키 | URI 변수로 엄격하게 인코딩(`+`, `/`, `=`). `%`가 있으면 Encoding 키로 보고 한 번 디코딩 |
| 응답 검증 | `totalCount`가 없거나 XML 오류 응답이면 예외. 첫 페이지만 처리하고 조용히 끝나는 것을 막음 |
| 스케줄 | 스케줄러 스레드 2개. 전체 동기화 중에도 상태 수집이 멈추지 않음 |

## 결과

- 얻은 것: 실행 중 발생한 504는 재시도로 자동 복구됐다. 인증키 형태와 관계없이 동작한다.
- 감수한 것: 재시도 때문에 최악의 경우 한 번의 호출이 수 분 걸릴 수 있다. 상태 수집은 다음 주기에 조회 기간을 늘려 보완한다(ADR-001).
