# ADR-002 전체 동기화의 데이터 정리 안전장치

- 상태: 승인

## 맥락

- 원본에서 철거된 충전기는 `delYn=Y`로 내려오거나, 응답에서 아예 사라진다. 정리하지 않으면 검색 결과에 계속 남는다.
- 정리 기준은 "이번 동기화에서 한 번도 갱신되지 않은 충전기"다. 그런데 이 기준은 **응답이 불완전하면 정상 데이터를 대량으로 지운다.**
  - 게이트웨이가 정상 코드(`resultCode=00`)로 빈 응답(`totalCount=0`)을 주는 경우
  - 페이지가 잘려서 오거나, 동기화 도중 원본이 바뀌어 페이지 경계가 밀리는 경우
  - 좌표가 잠시 이상해 저장하지 않은 충전기가 "사라진 것"으로 보이는 경우

## 결정

정리는 아래 조건을 **모두** 만족할 때만 한 번에 실행한다.

1. 실패한 페이지가 없을 것
2. 받은 건수와 **고유 충전기 수**가 모두 `totalCount`와 같고, 모든 페이지의 `totalCount`가 같을 것
3. 지울 충전기가 기존의 **5% 이하**일 것
4. 응답에는 있었지만 검증에서 걸러진 충전기는 "본 것"으로 표시해 정리 대상에서 뺄 것

정리 방식은 다음과 같다.

- `delYn=Y` 충전기도 같은 정리 경로로 지운다. 별도로 바로 지우는 경로가 없으므로 같은 안전장치를 거친다.
- 충전기가 하나도 남지 않은 충전소는 지우지 않고 `active=false`로 표시한다. 구독 등에서 참조될 수 있기 때문이다.
- 실패한 페이지 때문에 건너뛰면 WARN 로그만 남긴다(재시도로 해결되는 문제). 그 외 이유(건수 불일치, 비율 초과)로 건너뛰면 저절로 풀리지 않을 수 있어 ERROR 로그와 지표 `collector.station.cleanup.pending`(정리 대기 건수)으로 알린다. 원본이 정상이라고 확인되면 `app.collector.max-stale-ratio`를 일시적으로 올려 다시 동기화한다.
- 동기화의 모든 페이지에 시작 시각 하나를 기록하고, `updated_at`은 더 최근 값을 유지한다. 동기화 도중 시계가 보정되거나 동기화가 겹쳐도 방금 갱신한 행이 정리되지 않는다.

## 검토한 대안

| 대안 | 채택하지 않은 이유 |
|---|---|
| 정리하지 않음 | 철거된 충전기가 영구히 검색됨 |
| 페이지별로 바로 정리 | 부분 실패 시 정상 데이터를 지움 |
| 비율 제한만 사용 | 빈 응답일 때 비율 계산 자체가 의미 없어짐. 완전성 확인이 먼저 필요 |

## 결과

- 얻은 것: 불완전한 응답으로 데이터를 지우는 일이 없다. 테스트로 확인한 경우는 빈 응답, 잘린 페이지, 중복 키, 동기화 도중 건수 변경, 비율 초과, 검증 실패 항목이다.
- 감수한 것: 원본이 실제로 대규모 철거를 반영하면 정리가 멈춘다. 이 경우 지표를 보고 사람이 확인해야 한다.
- 서울 실데이터에서는 받은 건수·고유 건수·`totalCount`가 모두 76,593건으로 일치해 정상적으로 정리가 실행된다.
