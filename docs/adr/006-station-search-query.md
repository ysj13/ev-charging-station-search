# ADR-006 충전소 검색 쿼리 설계

- 상태: 승인

## 맥락

- 검색 조건: 키워드(이름·주소 부분 일치), 시군구, 좌표 반경, 빈자리 있는 곳만, 최소 출력. 결과에는 충전소별 충전기 수와 사용 가능 대수가 필요하다.
- 규모: 서울 충전소 약 1.3만 곳, 충전기 약 7.6만 대. 충전기 상태는 수 분 단위로 계속 바뀐다.
- 인증 없는 공개 API라 넓은 조건의 반복 호출도 감당해야 한다.

## 결정

| 항목 | 결정 |
|---|---|
| 반경 검색 | PostGIS 없이 **위경도 범위(B-tree 인덱스)로 먼저 거른 뒤 하버사인 거리**로 다시 거름. 범위는 하버사인과 같은 지구 반지름으로 계산하고 1% 여유를 둠 |
| 키워드 검색 | `pg_trgm` GIN 인덱스 + `ILIKE`. `%`, `_`, `\`는 이스케이프 |
| 집계 | 조건 판단(빈자리·최소 출력)은 충전기 **존재 여부(`EXISTS`)**로만. 충전기 수 집계는 **현재 페이지(최대 100곳)에만** |
| 정렬 | 좌표 검색은 거리순, 그 외에는 이름순. 실시간으로 바뀌는 빈자리 수로는 정렬하지 않음 |
| 조회 제한 | 검색 조건 하나는 필수. 결과의 앞 10,000건까지만 조회 가능 |
| 쿼리 작성 | JDBC 동적 SQL. 조건에 따라 바뀌는 것은 SQL 구조뿐이고 값은 모두 바인딩 |

## 검토한 대안

| 대안 | 채택하지 않은 이유 |
|---|---|
| PostGIS | 이 규모에서는 B-tree 범위 필터로 1ms 이내. 확장 설치·운영 부담만 늘어남 |
| Redis GEO | 키워드·필터·집계와 함께 쓰기 어렵고, 상태 정합성을 두 곳에서 맞춰야 함 |
| 빈자리 수로 정렬 | 페이지를 넘기는 사이 순서가 바뀌어 같은 충전소가 두 번 나오거나 빠짐 |
| 일치하는 모든 충전소를 집계 | 넓은 검색어("서울")에서 매 요청마다 충전기 7.6만 건을 집계 |

## 결과

**서울 실데이터 응답 시간**

| 요청 | 결과 | 응답 시간 |
|---|---|---|
| 반경 1km | 204곳 | 10ms |
| 반경 1km + 빈자리 + 50kW 이상 | 25곳 | 9ms |
| 키워드 3글자 이상 | 3곳 | 9ms |
| 시군구 | 1,047곳 | 13ms |
| 반경 10km | 7,182곳 | 40ms |
| 가장 넓은 키워드 ("서울", 주소에 서울이 들어간 거의 모든 충전소) | 12,992곳 | 78ms |

- 감수한 것: 트라이그램은 3글자부터 만들어진다. 그래서 2글자 검색어는 인덱스를 쓰지 못하고 전체를 훑는다(약 34ms).
- 감수한 것: `CREATE EXTENSION pg_trgm`에는 데이터베이스 `CREATE` 권한이 필요하다. 권한이 제한된 계정으로 운영하면 DBA가 미리 만들어 두어야 한다.
