# ADR-005 충전기 상태를 쓰는 주체를 감지기 하나로

- 상태: 승인

## 맥락

검색 API가 읽는 DB의 충전기 상태를 쓰는 곳이 두 군데였다.

- **전체 동기화:** 최신 상태로 직접 덮어씀
- **빈자리 감지기:** 상태 메시지를 처리하며 갱신

감지기는 Redis에 직전 상태가 없으면 DB의 상태를 기준으로 삼는다(ADR-004). 이때 경합이 생긴다.

1. 04시 전체 동기화가 어떤 충전기를 충전대기로 먼저 DB에 쓴다.
2. 같은 변경을 담은 메시지가 감지기에 도착한다.
3. 감지기가 보는 기준 상태가 이미 충전대기라서 **전이를 놓친다.**

## 결정

- 빈자리 감지가 켜져 있으면, 전체 동기화는 **새 충전기의 초기 상태만 넣는다.** 이미 있는 충전기의 상태는 바꾸지 않고 SNAPSHOT 메시지로만 전달한다.
- 충전기 상태를 쓰는 주체는 감지기 하나다.
- 감지기를 끄고 운영하면 DB 상태를 갱신할 곳이 동기화뿐이다. 이 경우에는 동기화가 더 최신 상태일 때만 직접 덮어쓴다(설정 `app.detector.enabled`로 분기).
- 감지기는 `updated_at`을 건드리지 않는다. `updated_at`은 전체 동기화가 "응답에 있었던 충전기"를 표시하는 용도다(ADR-002).

## 결과

- 얻은 것: DB가 감지기보다 앞서 가는 경로가 없다. 그래서 Redis 대체 조회와 SNAPSHOT 따라잡기가 함께 성립한다. "동기화가 먼저 상태를 받은 경우에도 감지한다"는 통합 테스트로 확인했다.
- 감수한 것: 감지기가 밀리면 검색 결과의 상태도 그만큼 늦게 갱신된다. 컨슈머 랙으로 감시한다.
