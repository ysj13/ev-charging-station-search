# ADR-008 Kafka와 RabbitMQ의 역할 분리

- 상태: 승인 (구현은 [ADR-010](010-vacancy-notification-delivery.md))

## 맥락

빈자리 알림까지 가려면 성격이 다른 두 종류의 메시지를 다뤄야 한다.

- **사실(이벤트):** "충전소 A의 1번 충전기가 비었다." 여러 소비자가 구독하고, 다시 처리할 수 있어야 한다.
- **할 일(작업):** "사용자 X에게 알림을 보내라." 사용자마다 따로 성공·실패하고, 실패한 것만 다시 시도해야 한다.

## 결정

| 구분 | Kafka | RabbitMQ |
|---|---|---|
| 다루는 것 | 상태 메시지(`charger.status`), 빈자리 이벤트(`charger.available`) | 사용자별 알림 발송 작업(`notification.send.queue`) |
| 쓰는 이유 | 이벤트 보존과 재처리, 여러 소비자 그룹의 독립 구독, 파티션 단위 순서 보장 | 메시지 단위 ACK, 개별 재시도, DLX/DLQ |

흐름: `charger.available` → 구독 매칭(이벤트 1건 → 구독자 N명) → RabbitMQ 발송 작업 → 알림 발송 → 최종 실패 시 DLQ

## 검토한 대안

| 대안 | 판단 |
|---|---|
| Kafka만 사용 (retry 토픽, DLT) | 가능함. 다만 사용자별 개별 재시도와 지연 재시도를 직접 구현해야 함 |
| RabbitMQ만 사용 | 이벤트 재처리와 여러 소비자의 독립 구독이 어려움 |

## 결과

- 얻은 것: 각 메시지 성격에 맞는 도구를 쓴다. 빈자리 감지와 알림 발송이 서로 독립적으로 장애를 견딘다.
- 감수한 것: 운영할 인프라가 하나 늘어난다.
- 알림 소비자는 (구독, `eventId`) 유니크 제약으로 중복을 거르고, `source`가 `MANUAL`인 이벤트는 개발 도구를 켠 환경에서만 알린다(ADR-010).
